### [CI/CD Explained: The DevOps Skill That Makes You 10x More Valuable ](https://www.youtube.com/watch?v=AknbizcLq4w&t=17s)

CI

- test smaller code changes frequently before merging them into the made branch

CD

- address problems and bottlenecks through automations
- automate testing, building and applying deployment
- e2e tests, security scanning and tests
- testing / staging environments
- performance, compliance and security tests

Deployment strategies

- Canary deployment (deploy to portions of users in stages and monitoring = progressive roll-out)
- Blue / green deployment (two environments hosting the current and the new version of the app, in the case of failures in the new version, traffic is redirected to the current version)

### [The Microservices Scam Nobody Talks About](https://www.youtube.com/watch?v=6e9B7q3gvYY)

- Distributed monolith problem: if the business logic is coupled but the code is distributed to several services; small changes require coordination and are failure prone
- Network calls are expensive compared to in-process function calls
- Additional compute and orchestration overhead, observability and logging costs
- Overwhelms the team and especially the DevOps members
- Difficult maintenance
- Alternative: modular monolith with clear insulation inside one structure; one deployable with clear internal boundaries, distribute only when there's a specific measurable reason to
- AI tools are only reliable where the architecture is modular and decoupled, only context where a change can be isolated and verified quickly
- System architecture mirrors communication strcture; if several teams have to coordinate to release a service, then the logic is coupled
- Restructuring ownership should precede restructuring the code
- Industry is moving away from microservices to modular monoliths; microservices only pay off when you actually need independent scaling of the service level or organisation is too large for shared deployment
- With a modular monolith, you can move a module out to a microservice at a later stage if needed
