#### Ep. 1: Project Setup & Intro

- Agents write in their own style, so it's recommended to format (using prettier) or use guardrails (using eslint)
- If your agent makes the same error, you could customise eslint to target it
- Recommended to add tests; with the rise of agents, TDD is becoming popular once again
- Agents seem to prefer writing pure CSS to tailwind
- Svelte has templates for authentication, which can guide the agent; boilerplate that the agent can change
- Use the generated cli config to save tokens and avoid agent errors (svelte config, vite config, playwright config, db config etc)

#### Ep. 2 AI Agent Setup & MCP

- Svelte released a new major version recently (ver 5), which has a syntax change; AI agents can have issues with syntax changes (generate legacy code)
- Svelte has an MCP = series of instructions and tools for the AI agents
- You can use multiple clients for large projects
- AGENTS.md has the available MCP tools listed (has to be included into CLAUDE.md if Claude is used)
- Svelte provides access to documentatio and static code analysis auto-fixer
- In the agent chat window, you can add MCP Resources (in the form of .md files) as context (resources exposed by the Svelte MCP server)
- You can also add respurces through a prompt

  `/mcp.svelte.svelte-task // Injects instructions for the AI into your prompt when you trigger a prompt through it`

- The Svelte auto-fixer runs static analysis after agent code generation and fixes legacy code and other issues
- The Svelte auto-fixer also outputs instructions to the AI on how to fix issues that cannot be auto-fixed (+ is configured to require a rerun of the auto-fixer tool after agent is finished with corrections)
- The Svelte auto-fixer tool gives appropriate suggestions for common AI agent mistakes
- An old model (GPT 4.1) was able to produce good and Svelte 5 compliant code thanks to the tools provided by the Svelte MCP server in the demo
- Don't add MCP servers to your project blindly, because you can expose the agent to malicious code; add only vetted and trusted servers (ex official Svelte MCP)
- Only enable an MCP when you're working on a relevant project, disable MCPs for technologies you're not using (to keep the context clean); the more context you consume, the "dumber" the model becomes

### Ep. 3 Context Management

- Context is the most precious resource in the agentic workflow; tools to aid context management = skills and subagent
- The Agent Skills spec is a lightweight, open format for extending Ai agent capabilities with specialised knowledge and workflows (just like an MCP server, they also allow you to add context and knowledge to the model after the training stage)
- Skills are considered a way to save context and add only specific context that is needed
- Anthropic offers skills (ex frontend-design)
