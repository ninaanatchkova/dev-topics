### [WebSocket and Its Difference from HTTP](https://www.geeksforgeeks.org/web-tech/what-is-web-socket-and-how-it-is-different-from-the-http/)

- Two main ways for handling data in web applications: real-time and non-real-time (upon client request)
- HTTP follows a request-response model where the connection closes after each request, so it cannot be used for real-time updates; each request carries full HTTP headers (increased overhead when it comes to frequent updates)
- WebSocket enables persistent, full-duplex communication between client and server for real-time data exchange (overhead reduced, exchanging only message data)
- WebSocket connection is established through initiation and handshake and has to be explicitly closed by client or server

### [How Do WebSockets Work?](https://blog.postman.com/how-do-websockets-work/)

- Use cases: chat and messaging, collaborative editing, live dashboards, gaming, notifications
- Security considerations: Always use WSS, Validate origin and implement authentication, implement rate limiting and validate all incoming messages, limit message size and validate data structures ot prevent the transmission of malicious payloads
- Common mistakes: not handling disconnection, sending too much data, not monitoring send queue length, poor error handling, not considering fallback mechanisms for connection for restricted environments (ex. corporate firewall)
