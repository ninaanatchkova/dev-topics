#### Ep. 4: TDD & Git

- Git is a very good tool for tracking changes made by agents
- The agent can be prompted to change specific portions of code with very specific instructions
- TDD can be used with agents
- Sometimes the agent won't test exactly what it's asked to test
- if you use TDD, you start with a failing test and can ask the agent to write code until the test is fixed (TDD workflow)

#### Ep. 5 Free prompt vs Plan mode

- Agents can struggle with big tasks
- Refactoring code is an example of a big task
- Build agent = main agent
- Plan agent = cannot touch the code, it figures out series of steps to help the build agent build the task
- The plan can be saved to a file, reviewed or used in cases where the build agent can't complete it in a single session
- If you're too specific in your prompt, you will steer the agent a certain way; you can work with the agent so that it asks you questions (you can prompt the agent to ask you questions)
- You can create an agent configured to look at specific part of the code or look for a pattern
- You can create a new session with clean context once the plan is complete and ask the build agent to implement the plan

#### Ep. 6 Harness curation

- You can prompt the agent to write its own skill and review it before adding it (for example, design system rules or CSS constraints and conventions)
- You can make the skill as specific as possible to your codebase
- If the agent is missing some knowledge that is needed when working on any part of the codebase, it can be added to AGENTS.md
- Don't put information that the agent can infer from the codebase
- You can direct the agent to use existing scripts in package.json instead of creating its own migrations or launching dev servers (for example)
- You can create a "Grill me" agent that will ask you questions and modify the plan, this can explore a lot of edge cases but it can also ask many unnecessary questions, so it should be used only when needed

#### Ep. 7 Code review tools

- We can use the same tools we use for ensuring code quality written by developers with agents (testing, code reviewing)
- Agentic engineering differs from vibe coding in that there are steps taken and techniques used to ensure code quality; the goal is productivity gain without losing control over the code
- When using agents, generated code volume increases dramatically, so reviewing the code becomes a bottle-neck
- AI can also help with code reviews
- Some AI reviewers may leave unnecessary comments, so you can configure certain settings to ensure a reasonable amount of comments or specific goals for the review
- The AI reviewer doesn't have the whole codebase as context but just the changes in the MR
- Sometimes the AI can give bad suggestions
- Can be used to facillitate reviews by pre-reviewing the MR, before the team takes a look at it

#### Ep. 8 Monitoring & Bug Tracking

- AI can be used in monitoring production code
- Before the agentic era, observability was needed to monitor production code, now agents can also use the monitoring logs to find bugs and work on fixes
- The monitoring AI can create a plan for the codefix

#### Ep. 9 Redesign

- You can redesign a project using an agent with a design skill
- A good test coverage will ensure that the project still works after the redesign

### [Generative AI's Greatest Flaw](https://www.youtube.com/watch?v=rAEqP9VEhe8)

- Prompt injection is an agent vulnerability (has a lot of similarities to an SQL injection attack)
- Will be an issue once agents work with more sensitive data and have more access to personal accounts and records
- There are ways to mitigate vulnerabilities but they will always exist
- Validate prompts and audit incoming data (no foolproof system to do this)
- Write tests to mimic possible attacks
- SQL solution: parameterised queries, where you separate the query from the data (injection in the data is read as data and not a query)
- LLMs don't work this way; you can attempt it in the training but malicious actors will most likely eventually find a way to circumvent this

### [Full Walkthrough: Worflow for AI Coding - Matt Pocock](https://www.youtube.com/watch?v=-QFHIoCo-Ko&list=PLn9NFIkaxC8FiWf8yAg8rBlhvi2nwYr8r&index=170)

- Principles of software development work really well with agents too, so agentic engineering is not a paradigm shift
- LLMs have a smart zone and a dumb zone
- The beginning of a conversation with AI is when it does its best work because the attention relationships are the least strained
- Around 40% or 100K context, the model becomes dumber
- It's important to size your tasks in a way that the AI can handle them without going into the dumb zone
- Working until the context fills up and then compacting is not the best strategy
- Common practice: Multi-phase plan
