**Reason**: Wanted more background on why styles declared with !important on a CSS Cascade Layer with the least precedence take precedence over styles declared with !important on cascade layers with more precedence

### Notes

According to the [CSS Cascading and Inheritance Module Level 5](https://drafts.csswg.org/css-cascade-5/#importance) spec:

**CSS attempts to create a balance of power between author and user style sheets. By default, rules in an author’s style sheet override those in a user’s style sheet, which override those in the user-agent’s default style sheet. To balance this, a declaration can be marked important, which increases its weight in the cascade and inverts the order of precedence.**

**CSS: Cascade origin**

- User agent (web browser default styles)
- Local user (user accessiblity and other preferences such as font-size or contrast)
- Author styles (styles authored by the author of the webpage)

**Least to most specific styles**

USER AGENT (base) < LOCAL USER (base) < AUTHOR STYLES (base) < AUTHOR STYLES !important < LOCAL USER !important < USER AGENT !important

- With cascade layers, unlayered styles are more important than layered styles

Author @layer < Author normal < Author normal !important < Author @layer !important

**Conclusion**: Reason for !important behaviour was not explicitly stated, but it looks like it is meant to invert precedence rather than bump precedence (the way increasing specificity would)
