Choosing the right type of database

- RDBMS (Relational Database Management Systems)
- NoSQL databases

Relational Databases

- Use SQL for founding and manipulating data
- consist of tables (columns = fields / attributes, rows = single records)
- support complex joint operations
- provide robust data consistency and integrity especially for transactions
- transcations = a sequence of one or more operations performed as an atomic unit; follow the ACID acronym (atomicity, consistency, isolation, durability)

Non-relational Databases

- Diffenent types: document stores (MongoDB), wide-column stores (Cassandra), key-value stores (Redis), Graph (Neo4G)
- Can handle highly dynamic and large data sets
- Optimised for low-latency and scalability

Main approaches for scaling: Vertical vs Horizontal Scaling

Vertical scaling (Scale up)

- Adding more resources to an existing server (RAM, CPU)
- limit on how much you can add
- lack of redundancy, if the single server goes down, the whole application will be down

Horizontal scaling (Scale out)

- Add more servers to share the load
- load balancers are used to distribute traffic to the servers

Load balancing strategies

- Round Robin: each server receives a request in order; good option when all servers have similar capabilities
- Least Connections: sends the request to the server with the smallest number of requests; useful when sessions have variable length
- Least Response Time: good option when you have different servers with different capabilities
- IP Hash: sends request based on hashing the client IP; useful when you want to send requests made by the same client to the same server
- Weighted alrorithms: weigthed versions of the above algorithm
- Geographical algorithms: redirects client to the geographically closest server
- Consistent hashing

Load balancers have a health check function to check whether servers are available
