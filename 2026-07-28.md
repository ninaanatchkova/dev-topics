Step 1: Build a Single-Server Setup

- determine request flow and traffic sources
- to handle increased traffic: separate web tier (handling requests) and data tier (database)

Choosing the right type of database

- RDBMS (Relational Database Management Systems)
- NoSQL databases

Relational Databases

- Use SQL for founding and manipulating data
- consist of tables (columns = fields / attributes, rows = single records)
- support complex joint operations
- provide robust data consistency and integrity especially for transactions
- transcations = a sequence of one or more operations performed as an atomic unit; follow the ACID acronym (atomicity, consistency, isolation, durability)

Non-relational Databases

- Diffenent types: document stores (MongoDB), wide-column stores (Cassandra), key-value stores (Redis), Graph (Neo4G)
- Can handle highly dynamic and large data sets
- Optimised for low-latency and scalability

Main approaches for scaling: Vertical vs Horizontal Scaling

Vertical scaling (Scale up)

- Adding more resources to an existing server (RAM, CPU)
- limit on how much you can add
- lack of redundancy, if the single server goes down, the whole application will be down

Horizontal scaling (Scale out)

- Add more servers to share the load
- load balancers are used to distribute traffic to the servers

Load balancing strategies

- Round Robin: each server receives a request in order; good option when all servers have similar capabilities
- Least Connections: sends the request to the server with the smallest number of requests; useful when sessions have variable length
- Least Response Time: good option when you have different servers with different capabilities
- IP Hash: sends request based on hashing the client IP; useful when you want to send requests made by the same client to the same server
- Weighted alrorithms: weigthed versions of the above algorithm
- Geographical algorithms: redirects client to the geographically closest server
- Consistent hashing

Load balancers have a health check function to check whether servers are available

Types of load balancers

- software (ex. nginx, you can install it on your servers)
- hardware (separate device)
- cloud (ex. AWS Elastic load balancer, adds virtual servers on demand
  )

Single point of failure

- a point which can take the entire system down if a failure in this point occurs
- such points are vulnerable to malicious attacks
- a single db is a typical example, but a single-load balancer is also a single point of failure
- can be avoided through different load-balancing strategies

API Design

- API = contract that defines: what requests can be made, how to make them, what responses to expect
- API = abstraction mechanism
- defines service boundaries

Types of APIs

- REST: resource-based (organised around resources using HTTP methods), stateless, standardise methods
- GraphQL: use query language, single endpoint, operations: query (read), mutate (write), subscription (real-time), recommended for complex UIs
- gRPC

Key Design Principles

- Consistency (consistent naming, consistent patterns)
- Simplicity (focus on core use cases, intuitive design)
- Security (authentication, authorisation, input validation, rate limiting)
- Performance (caching strategies, pagination, minimize payloads, reduce round trips)
- the choice of protocols influences API design

The API Design Process

- identify core use cases and user stories
- define scope and boundaries
- determine performance requirements (identify possible bottenecks)
- consider security constraints (authentication, authorisation, rate limiting)

Design Approaches

- top-down: start with high-leve requirements and workflow
- bottom-up: begin with existing data models and capabilities
- contract-first: define the API contract before implementation
